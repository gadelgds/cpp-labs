### Задача №1. Небуферизированный ввод-вывод (`FILE_FLAG_NO_BUFFERING`)

* **Исходный файл для копирования:** [`task1_no_buffering_bench.cpp`](task1_no_buffering_bench.cpp)

#### Условие
Написать программу, которая создает тестовый файл размером 10 МБ и заполняет его случайными символами.
Реализовать функцию чтения файла с использованием флага `FILE_FLAG_NO_BUFFERING`.
Продемонстрировать возникновение ошибки `ERROR_INVALID_PARAMETER` (код 87), попытавшись считать данные в невыровненный буфер (например, стандартный `char buf[1000]`) или с невыровненным смещением.
Исправить ошибку, применив функцию `VirtualAlloc` для выделения буфера, выровненного по границе страницы/сектора (4096 байт), и скорректировать размер чтения до величины, кратной 4096 байтам.
Сравнить скорость последовательного чтения файла с флагом `FILE_FLAG_NO_BUFFERING` и без него (со стандартным кэшированием) при помощи высокоточного таймера (`QueryPerformanceCounter`).

#### Построчный разбор реализации:
1. `GenerateRandomFile(testFile, 10MB);` — создает файл 10 МБ со случайными символами.
2. `CreateFileW(..., FILE_FLAG_NO_BUFFERING, ...);` — флаг заставляет ядро обойти системный кэш страниц. Данные передаются аппаратно через DMA напрямую в буфер процесса.
3. **Почему возникает ошибка 87 (`ERROR_INVALID_PARAMETER`):**
   * Контроллер накопителя требует строгого соблюдения правил:
     1. Базовый адрес буфера в ОЗУ обязан быть выровнен на границу сектора (кратен 4096 байтам);
     2. Смещение в файле обязано быть кратно 4096 байтам;
     3. Объем передаваемых байт (`nNumberOfBytesToRead`) обязан быть строго кратен 4096 байтам.
   * Стандартный массив на стеке `char unalignedBuf[1000]` имеет размер 1000 (не кратен 4096) и адрес, не кратный 4096, поэтому `ReadFile` возвращает `FALSE` и ошибку 87.
4. **Исправление через `VirtualAlloc`:**
   ```cpp
   void* alignedBuffer = VirtualAlloc(NULL, 64 * 1024, MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);
   ```
   Диспетчер памяти Windows выделяет память целыми страницами, поэтому возвращаемый адрес **автоматически выровнен по границе 4096 байт**. Размер буфера 64 КБ кратен 4096, и вызов `ReadFile` завершается успешно.
5. **Сравнение скорости через `QueryPerformanceCounter`:**
   * Стандартный I/O (с кэшем) выигрывает за счет системного упреждающего чтения (Read-Ahead) в RAM;
   * Небуферизированный I/O эффективен на огромных объемах (базы данных, видеомонтаж), исключая двойную буферизацию.

### Задача №2. Симуляция СУБД: случайный доступ, проецирование и сброс TLB

* **Исходный файл для копирования:** [`task2_dbms_sim_filemapping_tlb.cpp`](task2_dbms_sim_filemapping_tlb.cpp)

#### Условие
Создать бинарный файл объемом 16 МБ, содержащий последовательность целых чисел (`int`).
Написать программу, симулирующую работу СУБД (10 000 случайных чтений и модификаций) в двух режимах:
* **Режим А (Стандартный I/O):** `ReadFile / WriteFile` со стандартным кэшированием.
* **Режим Б (Ручное проецирование):** `CreateFileMapping` и скользящее окно `MapViewOfFile` с принудительным `UnmapViewOfFile` после каждой модификации.
Замерить время выполнения 10 000 операций для обоих режимов и объяснить просадку производительности из-за сброса TLB (**TLB Flush**).

#### Построчный разбор и физика процесса:
1. **Режим А (Стандартный кэшированный I/O):**
   * `SetFilePointerEx(hFileA, offset, NULL, FILE_BEGIN);` — позиционирование указателя;
   * `ReadFile` $\to$ модификация $\to$ `SetFilePointerEx` $\to$ `WriteFile`.
   * Страницы файла один раз загружаются в системный файловый кэш ОС в оперативной памяти и остаются там. Обращения происходят быстро без перестройки таблиц виртуальной памяти.
2. **Режим Б (Скользящее окно с частым размонтированием):**
   * `MapViewOfFile(hMappingB, FILE_MAP_ALL_ACCESS, 0, alignedOffset, windowSize);` — отображение 64 КБ окна;
   * Модификация ячейки через указатель `pView`;
   * `UnmapViewOfFile(pView);` — принудительное немедленное размонтирование.
3. **Почему Режим Б работает медленнее (накладные расходы TLB Flush):**
   * **TLB (Translation Lookaside Buffer)** — это высокоскоростной аппаратный кэш процессора, хранящий трансляции "виртуальный адрес $\to$ физический фрейм ОЗУ".
   * При каждом вызове `UnmapViewOfFile` ядро Windows обязано удалить записи из таблицы страниц процесса и выполнить процессорную инструкцию **`INVLPG`** или перезаписать регистр управления **`CR3`**, сбрасывая кэш TLB процессора (**TLB Flush**).
   * При следующем `MapViewOfFile` процессор сталкивается с промахами TLB (TLB Miss) и аппаратными прерываниями **Page Fault**.
   * Выполнение 10 000 циклов монтирования/размонтирования создает колоссальные накладные расходы на уровне процессора и диспетчера памяти ядра.

### Задача №3. Прямое выделение памяти у ядра Windows (`VirtualAlloc`)

* **Исходный файл для копирования:** [`task3_direct_kernel_memory.cpp`](task3_direct_kernel_memory.cpp)

#### Условие
Написать программу, которая запрашивает у пользователя размер массива целых чисел (например, 10 000 элементов).
Выделить под этот массив память напрямую у ядра ОС Windows.
Заполнить массив числами (например, квадратами их индексов) и вывести первые 10 элементов на экран.
Освободить память.

#### Построчный разбор системных вызовов:
1. `size_t sizeInBytes = count * sizeof(int);` — расчет точного размера в байтах (для 10 000 `int` = 40 000 байт).
2. `VirtualAlloc(NULL, sizeInBytes, MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);` — **прямое выделение у ядра Windows**:
   * `NULL` — ядро Windows самостоятельно выбирает свободный диапазон виртуальных адресов;
   * `MEM_RESERVE` — резервирует непрерывный диапазон адресов в адресном пространстве процесса (без расхода физической RAM);
   * `MEM_COMMIT` — привязывает физические страницы оперативной памяти (или файлы подкачки) к зарезервированному адресному диапазону;
   * `PAGE_READWRITE` — устанавливает атрибуты защиты страниц на уровне MMU: разрешено чтение и запись.
3. `pArray[i] = static_cast<int>(i * i);` — заполнение элементов массива квадратами индексов ($0, 1, 4, 9, 16, 25...$).
4. `VirtualFree(pArray, 0, MEM_RELEASE);` — **прямой возврат страниц памяти ядру Windows**:
   * `MEM_RELEASE` — де-коммитирует физические страницы и освобождает виртуальный адресный диапазон;
   * **Важное правило Win32:** при флаге `MEM_RELEASE` параметр размера *обязан быть строго равен 0* — ядро автоматически освобождает весь исходный блок страниц.
