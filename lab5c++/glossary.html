Как читать словарь. Здесь объяснены все трудные слова из лабы 5 — коротко и простыми словами. Буфер — это кусок памяти, куда программа кладёт данные. Диск — это устройство, где файлы хранятся постоянно (жёсткий диск или SSD). Смещение — это номер байта в файле, с которого начинается чтение. Ядро Windows — это главная часть Windows, которая управляет памятью и дисками. Физическая память — это настоящая память компьютера.

Виртуальная память
Задача №3

Каждая программа видит своё собственное адресное пространство, как будто вся память компьютера принадлежит только ей. На самом деле Windows переводит адреса программы в настоящую физическую память, поэтому две программы могут использовать один и тот же адрес и не мешать друг другу.

Пример: Два человека живут в разных квартирах с одинаковым номером — почтальон (Windows) знает, кому какое письмо нести.
Выравнивание
Задача №1

Буфер считается выровненным, когда его адрес делится на 4096 без остатка. Диск работает только целыми секторами, поэтому программа должна ставить буфер точно на границу сектора.

Пример: Книги на полке ставят с края полки, а не с середины.
Гранулярность распределения
Задача №2

Шаг в 64 КБ, с которым Windows выдаёт адреса: начало любого выделенного участка памяти всегда кратно 64 КБ. Программа не может попросить участок с произвольного адреса.

Пример: Забор ставят только по столбам, расстояние между столбами всегда одинаковое.
Небуферизированный ввод-вывод
Задача №1

Чтение и запись файла напрямую, без системного кэша: данные идут с диска сразу в буфер программы. Так работают базы данных, которым не нужна вторая копия данных в памяти Windows.

Пример: Покупатель забирает товар прямо со склада, а не ждёт, пока его выложат на полку магазина.
Ошибка 87 (ERROR_INVALID_PARAMETER)
Задача №1

Ответ Windows «неверные параметры»: программа попросила прочитать файл, но буфер, смещение в файле или размер чтения не кратны 4096. Чтение не выполняется, программа получает код 87 и должна исправить параметры.

Пример: Ключ не подходит к замку — дверь не открывается, и виноват не замок, а ключ.
Проецирование файла в память
Задача №2

Способ работать с файлом как с обычной памятью: Windows показывает файл в адресном пространстве программы, и программа читает и пишет его обычными действиями с памятью, без отдельных команд чтения и записи файла.

Пример: Книга лежит открытой на столе — читатель сразу берёт любую страницу, а не ходит за ней в библиотеку.
Сброс TLB
Задача №2

Очистка маленького кэша в процессоре, где хранятся переводы адресов в физическую память. Windows очищает этот кэш, когда меняет адреса программы, и после очистки процессор ищет переводы заново, поэтому работа замедляется.

Пример: Учитель стирает шпаргалку с доски, и ученикам приходится писать её заново.
Сектор
Задача №1

Самый маленький кусок диска, который диск читает или пишет за один раз; в этой лабе его размер — 4096 байт. Меньше одного сектора диск прочитать не может, поэтому программа всегда просит целое число секторов.

Пример: Кирпич — самая маленькая часть стены, стену строят только из целых кирпичей.
Системный кэш
Задачи №1, №2

Память, где Windows хранит копии данных из файлов, чтобы второй раз не ходить на диск. Первый раз файл читается с диска, а потом программа берёт данные из кэша — это гораздо быстрее.

Пример: Повар держит нож под рукой, а не ходит за ним на склад каждый раз.
Страница памяти
Задачи №1–№3

Кусок памяти размером 4096 байт; Windows делит всю память на такие куски и выдаёт программе память только целыми страницами.

Пример: Тетрадь состоит из листов, и продавец продаёт только целые листы, а не половинки.
СУБД
Задача №2

Программа для хранения данных и быстрого поиска среди них, например база данных с таблицами. СУБД хранит данные в файлах на диске и сама решает, какие данные держать в памяти.

Пример: Библиотекарь хранит книги и находит нужную книгу, не перебирая все полки.
TLB
Задача №2

Маленький и очень быстрый кэш в процессоре, где хранятся переводы адресов в физическую память. Процессор сначала смотрит в TLB, и только если перевода там нет, ищет адрес дольше.

Пример: Телефонная книга — человек звонит сразу, не вспоминая номер.
VirtualAlloc
Задачи №1, №3

Функция Windows, которая просит память напрямую у ядра Windows. Ядро даёт программе страницы памяти, а адрес начала всегда кратен 64 КБ — поэтому память от VirtualAlloc автоматически подходит для небуферизированного чтения.

Пример: Человек арендует склад напрямую у хозяина, а не через посредника.
FILE_FLAG_NO_BUFFERING
Задача №1

Флаг для открытия файла: говорит Windows не использовать системный кэш и передавать данные напрямую с диска в буфер программы. За это приходится платить строгими правилами: буфер, смещение и размер чтения должны быть кратны 4096, иначе Windows вернёт ошибку 87.

Пример: Курьер везёт посылку прямо покупателю, минуя склад.
MEM_COMMIT
Задачи №1, №3

Флаг для VirtualAlloc: говорит ядру Windows выделить настоящие физические страницы памяти. Без этого флага программа получает только забронированные адреса, а памяти под ними нет.

Пример: Хозяин не только бронирует стол, но и ставит на стол еду.
MEM_RESERVE
Задачи №1, №3

Флаг для VirtualAlloc: говорит ядру Windows забронировать диапазон адресов в адресном пространстве программы, чтобы никто другой его не занял. Физическая память при этом не выделяется — только адреса.

Пример: Человек бронирует стол в кафе, но еда на столе ещё не стоит.
QueryPerformanceCounter
Задачи №1, №2

Функция Windows для точного замера времени: программа вызывает её до и после работы, а потом делит разницу отметок таймера на частоту таймера и получает время в миллисекундах. Обычные часы для таких замеров слишком грубые.

Пример: Судья включает секундомер на старте забега и выключает на финише.
