Приведение типов, void* и MapViewOfFile

1. static_cast 2. void* в x64 3. MapViewOfFile со смещением
Задача 1 (Наизусть): Явное приведение типов через static_cast
task1_explicit_casting.cpp
task1_explicit_casting.cpp 
#include <iostream>
#include <iomanip>

int main() {
    #if defined(_WIN32)
    system("chcp 65001 > nul");
    #endif

    // Часть 1: long - static_cast(int)
    long valLong = 100000L;
    int valInt = 25000;
    long resultLong = valLong - static_cast<long>(valInt);

    // Часть 2: double - static_cast(float)
    double valDouble = 125.75;
    float valFloat = 25.25f;
    double resultDouble = valDouble - static_cast<double>(valFloat);

    std::cout << "resultLong: " << resultLong << std::endl;
    std::cout << std::fixed << std::setprecision(4);
    std::cout << "resultDouble: " << resultDouble << std::endl;

    return 0;
}
Подробный построчный разбор команд
static_cast<long>(valInt) Явное приведение типов времени компиляции (Compile-Time Cast). Гарантирует приведение типа int к типу long перед вычитанием.
static_cast<double>(valFloat) Расширяющее приведение 32-битного вещественного числа float к 64-битному представлению double стандарта IEEE 754.
Задача 2 (Самостоятельно): Указатели void* и разрядность x64
task2_void_pointers_x64.cpp
task2_void_pointers_x64.cpp 
#include <iostream>

int main() {
    #if defined(_WIN32)
    system("chcp 65001 > nul");
    #endif

    int numInt = 42;
    long numLong = 123456L;

    // Универсальные указатели void*
    void* ptrVoid1 = &numInt;
    void* ptrVoid2 = &numLong;

    // Обратное преобразование в типизированные указатели
    int* ptrInt = static_cast<int*>(ptrVoid1);
    long* ptrLong = static_cast<long*>(ptrVoid2);

    std::cout << "Значение numInt: " << *ptrInt << " (адрес: " << ptrInt << ")" << std::endl;
    std::cout << "Значение numLong: " << *ptrLong << " (адрес: " << ptrLong << ")" << std::endl;

    std::cout << "\n[Размеры в x64]:" << std::endl;
    std::cout << "sizeof(void*): " << sizeof(void*) << " байт (8 байт)" << std::endl;
    std::cout << "sizeof(int*):  " << sizeof(int*) << " байт (8 байт)" << std::endl;
    std::cout << "sizeof(int):   " << sizeof(int) << " байт (4 байта)" << std::endl;
    std::cout << "sizeof(long):  " << sizeof(long) << " байт (4 байта в Windows LLP64)" << std::endl;

    return 0;
}
Построчный разбор
void* ptrVoid1 = &numInt; Универсальный указатель. Принимает адрес любого типа. Разыменование *ptrVoid1 напрямую запрещено компилятором, так как размер типа void не определен.
static_cast<int*>(ptrVoid1) Явное обратное приведение к int*, после которого становится доступен оператор разыменования *ptrInt.
sizeof(void*) == 8 байт В 64-битной архитектуре (x64) любой указатель занимает ровно 8 байт (64 бита), независимо от типа данных, на которые он ссылается.
Задача 3 (Самостоятельно): Проецирование со смещением (Allocation Granularity)
task3_memory_mapped_offset.cpp
task3_memory_mapped_offset.cpp 
#include <windows.h>
#include <iostream>

int main() {
    #if defined(_WIN32)
    system("chcp 65001 > nul");
    #endif

    SYSTEM_INFO sysInfo;
    GetSystemInfo(&sysInfo);
    DWORD allocGranularity = sysInfo.dwAllocationGranularity; // 64 КБ (65536)

    HANDLE hFile = CreateFileW(L"mapped_large_test.txt", GENERIC_READ | GENERIC_WRITE, FILE_SHARE_READ, NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);
    HANDLE hMapping = CreateFileMappingW(hFile, NULL, PAGE_READONLY, 0, 0, NULL);

    // Смещение ОБЯЗАНО быть строго кратно allocGranularity (64 КБ)!
    size_t targetOffset = 2 * allocGranularity; // 128 КБ
    DWORD offsetLow = (DWORD)(targetOffset & 0xFFFFFFFF);
    DWORD offsetHigh = (DWORD)(targetOffset >> 32);

    const char* pView = (const char*)MapViewOfFile(hMapping, FILE_MAP_READ, offsetHigh, offsetLow, 1024);
    if (pView) {
        std::cout << "Спроецировано по виртуальному адресу: " << (void*)pView << std::endl;
        UnmapViewOfFile(pView);
    }

    CloseHandle(hMapping);
    CloseHandle(hFile);
    return 0;
}
Почему смещение не может быть случайным?
Allocation Granularity = 64 КБ (65 536 байт) Подсистема виртуальной памяти Windows отображает страницы файлов кратно аппаратной гранулярности распределения.
ERROR_MAPPED_ALIGNMENT (код 1132) Ошибка, которая немедленно возвращается функцией MapViewOfFile, если смещение (dwFileOffsetLow/High) не кратно 64 КБ.
