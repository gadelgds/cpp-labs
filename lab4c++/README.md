### Задача 1. Явное приведение типов через `static_cast` (Блок «Наизусть 72»)

* **Исходный файл для копирования:** [`task1_explicit_casting.cpp`](task1_explicit_casting.cpp)

#### Условие
Создайте новую переменную типа `long`, в которую запишите результат вычитания переменной `int` из переменной `long`. Перед выполнением вычитания, значение переменной `int` должно быть явно приведено к типу `long` с помощью `static_cast<long>()` (то же самое с `float` и `double`).

#### Построчный разбор команд:
1. `long valLong = 100000L;` — объявляет 32-битную целочисленную переменную типа `long` с суффиксом `L`.
2. `int valInt = 25000;` — объявляет переменную базового типа `int`.
3. `static_cast<long>(valInt)` — **явное приведение типов языка C++**. Компилятор статически на этапе сборки преобразует представление значения переменной `valInt` к целевому типу `long`.
4. `long resultLong = valLong - static_cast<long>(valInt);` — вычитание двух операндов одинакового типа `long` без скрытых неявных преобразований.
5. `double valDouble = 125.75; float valFloat = 25.25f;` — переменные двойной (64 бита) и одинарной (32 бита) точности с плавающей точкой стандарта IEEE 754.
6. `static_cast<double>(valFloat)` — явное расширение 32-битного вещественного числа до 64-битного типа `double`.
7. `double resultDouble = valDouble - static_cast<double>(valFloat);` — вычитание двух чисел `double`, результат сохраняет максимальную точность.

### Задача 2. Универсальные указатели `void*` и размеры типов в x64 (Блок «Самостоятельно»)

* **Исходный файл для копирования:** [`task2_void_pointers_x64.cpp`](task2_void_pointers_x64.cpp)

#### Условие
Создайте переменную типа `int`/`long`. Инициализируйте их любыми произвольными значениями.
Создайте независимый универсальный указатель типа `void*`. Запишите в них адрес созданной переменной.
Преобразуйте указатели `void*` обратно в исходный тип `int*`/`long*`/`long long*`. Извлеките значения из памяти и выведите их на экран. Определить размер указателя и переменных в х64.

#### Построчный разбор команд:
1. `int numInt = 42; long numLong = 123456L;` — создание целочисленных переменных на стеке программы.
2. `void* ptrVoid1 = &numInt;` — универсальный указатель на нетипизированную память. В C++ тип `void*` может сохранять адрес любого типа данных без явного приведения. Однако прямой доступ по адресу `*ptrVoid1` запрещен стандартом C++, так как тип `void` не имеет размера.
3. `int* ptrInt = static_cast<int*>(ptrVoid1);` — явное обратное преобразование `void*` в строго типизированный указатель `int*`.
4. `*ptrInt` — оператор разыменования: считывает ровно 4 байта из ячейки памяти и интерпретирует их как число `int`.
5. **Размеры в 64-битной архитектуре Windows (модель данных LLP64):**
   * `sizeof(void*) == 8 байт` (любой указатель в 64-битном виртуальном пространстве занимает ровно 8 байт);
   * `sizeof(int*) == 8 байт`, `sizeof(long*) == 8 байт`;
   * `sizeof(int) == 4 байта`, `sizeof(long) == 4 байта`, `sizeof(long long) == 8 байт`.

### Задача 3. Проецирование файла со смещением (`MapViewOfFile`)

* **Исходный файл для копирования:** [`task3_memory_mapped_offset.cpp`](task3_memory_mapped_offset.cpp)

#### Условие
Напишите программу, которая имитирует чтение огромного файла порциями. Программа должна спроецировать текстовый файл, но вызвать `MapViewOfFile` так, чтобы отобразить не начало файла, а строго его кусок, находящийся на определенном смещении. Смещение (параметры `dwFileOffsetHigh` и `dwFileOffsetLow` в `MapViewOfFile`) **не может быть случайным**.

#### Почему смещение в `MapViewOfFile` не может быть случайным?
Диспетчер виртуальной памяти Windows (Virtual Memory Manager) отображает файлы в адресное пространство процесса на аппаратном уровне через модуль управления памятью процессора (MMU).
* Системная гранулярность распределения памяти (**Allocation Granularity**) в Windows для архитектур x86 и x64 составляет **64 КБ (65 536 байт)**.
* Если передать смещение, не кратное 64 КБ (например 500 байт), функция `MapViewOfFile` немедленно завершится с ошибкой **`ERROR_MAPPED_ALIGNMENT (код 1132)`**: *"Базовый адрес или смещение файла для указанного представления не имеют требуемого выравнивания"*.

#### Построчный разбор реализации:
1. `SYSTEM_INFO sysInfo; GetSystemInfo(&sysInfo);` — опрашивает ядро ОС о параметрах процессора и архитектуры.
2. `DWORD allocGranularity = sysInfo.dwAllocationGranularity;` — получает величину гранулярности (65 536 байт).
3. `CreateFileMappingW(hFile, NULL, PAGE_READONLY, 0, 0, NULL);` — создает объект ядра "секция" (File Mapping Object).
4. `size_t targetOffset = 2 * allocGranularity;` — вычисляет выровненное смещение (131 072 байт = 128 КБ), кратное 64 КБ.
5. `MapViewOfFile(hMapping, FILE_MAP_READ, offsetHigh, offsetLow, viewSize);` — отображает 1 КБ кусок файла, находящийся на смещении 128 КБ, прямо в виртуальную память процесса.
6. `UnmapViewOfFile(pView);` — размонтирует отображение и освобождает виртуальные адреса.
