Подробное объяснение различий моделей памяти

1. Windows x64 использует модель LLP64. Типы int и long остаются 32-битными (4 байта). Старый 32-битный код продолжает работать без изменений.

2. Указатели (void*) в x64 занимают 8 байт. 8 байт хранят 64 бита адреса.

3. Типы ULONG_PTR, DWORD_PTR и INT_PTR — целые числа шириной с указатель. В x86 они занимают 4 байта. В x64 они занимают 8 байт. Они безопасно хранят адреса.

    #if defined(_WIN32)

    #endif

Разбор ошибки и решения

В чём была ошибка: (DWORD)lpContext отбрасывает старшие 32 бита указателя в 64-битной сборке. Внутри ProcessData обратный каст в int* получает битый адрес. Разыменование *pNumber роняет программу. Код падения: 0xC0000005 (Access Violation).

Как исправлено: Программа заменяет DWORD на DWORD_PTR. В x86 он занимает 32 бита. В x64 он занимает 64 бита. Ни один бит адреса не теряется.

        NULL

    HANDLE hProcess = GetCurrentProcess();

6 экзаменационных вопросов по ОС (Фото 3)

В1
Вы запускаете ReadFile асинхронно. Потом вы сразу закрываете хэндл файла через CloseHandle. Вы не ждёте конца операции. Что произойдёт?
Итог: Драйвер держит ссылку, поэтому объект файла сразу не удалится. Операция отменяется. Если буфер был на стеке, произойдёт порча памяти!
  • Драйвер держит свою ссылку на File Object. Ссылка живёт до завершения пакета IRP.
  • Закрытие хэндла запускает IRP_MJ_CLEANUP (отмену I/O).
  • Если функция освободила буфер на стеке при выходе, DMA-контроллер запишет данные по старому адресу. Запись повредит память или уронит программу.
  • GetOverlappedResult возвращает ERROR_INVALID_HANDLE.
В2
Почему программа обнуляет поля структуры OVERLAPPED (например, через = {0} или memset)? Это критически важно.
  • Поля смещения (Offset / OffsetHigh): В асинхронных вызовах Windows берёт смещение для чтения только из этих полей. Мусорные байты заставят ядро читать файл со случайного смещения. Ядро вернёт ERROR_HANDLE_EOF.
  • Хэндл события (hEvent): Ядро примет мусорное значение за валидный хэндл. Ядро вызовет SetEvent(). Вызов даст ложные срабатывания в чужих объектах.
В3
Маленький файл (10 байт) хранится в NTFS как резидентный. Программа читает его через ReadFile с флагом OVERLAPPED. Будет ли реальная асинхронная задержка ввода-вывода?
Ответ: НЕТ. Реальной задержки ввода-вывода не будет!

Файлы до ~700 байт в NTFS хранятся внутри 1024-байтной записи MFT. Они хранятся как резидентный атрибут $DATA. Запись MFT уже находится в памяти (в кэше ядра). Функция ReadFile мгновенно копирует 10 байт из памяти в буфер. Функция синхронно возвращает TRUE.

В4
Как программа открывает файлы с именем $MFT?

Файловая система защищает прямой путь C:\$MFT. Она возвращает ERROR_ACCESS_DENIED.

  • Raw Volume Access: Программа открывает физический том с правами администратора: CreateFileW(L"\\\\.\\C:", ...). Программа читает записи через DeviceIoControl(FSCTL_GET_NTFS_FILE_RECORD).
  • USN Journal: Программа читает записи через API журнала изменений FSCTL_READ_USN_JOURNAL.
  • Теневые копии (VSS): Программа читает напрямую из Volume Shadow Copy.
В5
Почему в Windows файлы ИМЯ.txt и имя.txt — это один и тот же файл?
  • Подсистема Win32 регистронезависима: Для совместимости с DOS подсистема Win32 передаёт ядру флаг OBJ_CASE_INSENSITIVE. Подсистема приводит имена к верхнему регистру.
  • Ядро NT и NTFS поддерживают регистрозависимость: Файловая система NTFS сохраняет регистр букв (Case-Preserving). Ядро поддерживает регистрозависимость при вызове Native API (NtCreateFile без флага). В Windows 10/11 включите регистрозависимость папки командой fsutil.exe file setCaseSensitiveInfo <папка> enable.
В6
Как ОС узнаёт, свободен ли сектор на диске?
  • ОС оперирует кластерами. Кластер обычно равен 4 КБ. Кластер — это группа секторов.
  • Метафайл $Bitmap в NTFS: В корне тома находится битовая карта $Bitmap (запись 6 в MFT). Каждый бит соответствует кластеру. 0 означает «свободен». 1 означает «занят».
  • В FAT32: Таблица FAT хранит статус. Свободный кластер равен 0x00000000.
  • На уровне SSD: ОС сообщает контроллеру об освобождённых секторах. Команда: TRIM / Deallocate.
