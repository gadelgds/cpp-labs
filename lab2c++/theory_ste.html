Тема 1 • Задание 1 из Word

Венгерская нотация и типы Win32

Что это

Венгерская нотация — соглашение об именах переменных в Win32 API. Имя начинается с префикса из строчных букв. Префикс подсказывает тип или назначение переменной. Префикс — это не часть типа. Это только подсказка для читающего код. Компилятор на префикс не смотрит.

Нотация появилась во времена C без строгой типизации. Тогда перепутать указатель и число было легко. В современном C++ её роль меньше. Но весь Win32 API написан именно так. Поэтому префиксы надо уметь читать.

ПрефиксРасшифровкаЧто означаетПример

Типы Win32 из задания 1

LPCSTR = const char*. Это указатель на константную ANSI-строку (L — long pointer, P — pointer, C — const, STR — string). Буква C означает «только чтение». Через такой указатель текстовую строку менять нельзя.

LPVOID = void*. Это нетипизированный указатель на любой буфер. Его нельзя разыменовать напрямую. Сначала приведите его к конкретному типу.

HMODULE — хэндл загруженного модуля (.exe или .dll). По сути это базовый адрес модуля в памяти. В Win32 он равен HINSTANCE. HINSTANCE равен HANDLE.

DWORD = unsigned long. Это 32-битное беззнаковое целое. Тип всегда занимает 4 байта: и в x86, и в x64. Это важно для темы усечения ниже.

Типичная ошибка: Не читайте префикс как тип. cbSize — это не «тип cb». Это обычное 32-битное число. Имя подсказывает: в нём хранится размер в байтах. И наоборот: переменная без префикса может иметь любой тип. Префикс ни к чему не обязывает компилятор.

Тема применяется в файлах: 1_lab2_word/task1_types_sizeof.cpp (типы Win32), 1_lab2_word/task2_ptr_truncation_fix.cpp (lpContext), 1_lab2_word/task3_kernel_handles.cpp (hFile, hEvent, hProcess).

Тема 2 • task1_types_sizeof.cpp

Модели данных и sizeof: x86 / x64, LLP64

Что это

Модель данных — это правило. Правило задаёт размер каждого базового типа в байтах на данной платформе. Стандарт C++ фиксирует только соотношения (например, sizeof(char) == 1, sizeof(long) >= sizeof(int)). Точные размеры выбирает платформа. Поэтому одна и та же программа на разных системах видит разные размеры типов.

sizeof — оператор. Он возвращает размер типа или переменной в байтах. Компилятор вычисляет его во время компиляции (для обычных типов). Оператор не выполняет свой операнд: sizeof(a++) не увеличит a.

МодельГде действуетintlonglong longуказатель
ILP32Windows x86, Linux x864484
LLP64Windows x644488
LP64Linux / macOS x644888
Ключевые правила

1. В Windows x64 действует LLP64. Тип long остаётся 4 байта. Растут только long long и указатели. Microsoft сделала так, чтобы старый 32-битный код продолжал компилироваться без правок.

2. В Linux x64 действует LP64. Тип long равен 8 байтам. Тот же код под Linux даст другой sizeof(long). Не заучивайте размеры типов «вообще». Заучивайте размеры только для конкретной платформы.

3. Типы ULONG_PTR, DWORD_PTR и INT_PTR — целые числа шириной с указатель. В x86 они занимают 4 байта. В x64 они занимают 8 байт. Они безопасно хранят адреса в целых числах.

4. DWORD и LONG всегда занимают 4 байта. Это верно в обеих архитектурах. Не используйте их для хранения указателей.

Типичная ошибка: Не считайте, что long — это «длинное, значит 8 байт». В Windows это неверно. sizeof(long) == 4 и в x86, и в x64. Для гарантированных 8 байт используйте long long или int64_t.

Тема применяется в файле 1_lab2_word/task1_types_sizeof.cpp. Программа печатает реальные размеры на машине, где запущена. Запустите её в x86- и x64-сборках. Сравните вывод.

Тема 3 • task2_ptr_truncation_fix.cpp

Усечение указателя (pointer truncation)

Что это

Указатель в x64 занимает 8 байт. 8 байт хранят 64 бита адреса, например 0x00007FF7A1B2C3D4. Если записать такой адрес в 32-битное целое (DWORD, 4 байта), старшие 32 бита отбрасываются. Адрес «усекается» до 0xA1B2C3D4. Обратное преобразование даёт другой, мусорный адрес.

В x86 проблемы нет. Указатель и DWORD занимают по 4 байта. Ошибка проявляется только при переходе на 64 бита. Это классический баг портирования старого кода.

ШагЧто происходитРезультат
Ошибочный кодDWORD t = (DWORD)lpContext; в x64Старшие 32 бита адреса потеряны. Компилятор даёт предупреждение C4311.
Обратный кастint* p = (int*)t; внутри функцииПрограмма восстанавливает чужой адрес вида 0x00000000A1B2C3D4.
Разыменование*p читает по битому адресу.Программа падает: Access Violation, код 0xC0000005.
ИсправлениеDWORD_PTR t = (DWORD_PTR)lpContext;В x64 — 8 байт, адрес цел. В x86 — 4 байта, адрес тоже цел.
Ключевые правила

1. Храните адрес только в указателе или в целом «шириной с указатель». Используйте DWORD_PTR, ULONG_PTR, INT_PTR (Win32) или uintptr_t, intptr_t. Никогда не храните адрес в DWORD, int или long.

2. reinterpret_cast<int*>(x) — явное низкоуровневое преобразование целого в указатель. Компилятор доверяет программисту. Компилятор не проверяет адрес. Проверка if (pNumber != nullptr) ловит только ноль. Битый ненулевой адрес проверка не ловит.

3. Предупреждение компилятора C4311 («pointer truncation») — это не косметика. Это сигнал о потере данных. Сборка с /W4 и /WX ловит такие баги до запуска. Флаг /WX делает предупреждения ошибками.

Типичная ошибка: «На моём компьютере работает». Усечённый адрес может случайно указывать на доступную память. Программа проработает, пока не получит другой адрес. Например, после перезапуска из-за ASLR — случайного базового адреса. Баг плавающий. Ловите его по предупреждению компилятора, а не по тестам.

Тема применяется в файле 1_lab2_word/task2_ptr_truncation_fix.cpp. Это исправленная версия. Параметр ProcessData и переменная SAFE_PTR имеют тип DWORD_PTR.

Тема 4 • task3_kernel_handles.cpp

Хэндлы объектов ядра Windows (HANDLE)

Что это

Ядро Windows не даёт программам прямых указателей на свои внутренние структуры. Прямые указатели — это дыра в безопасности. Вместо этого программа получает хэндл (HANDLE). Хэндл — небольшое число. Хэндл — индекс в таблице хэндлов процесса. По этому индексу ядро само находит объект: файл, событие, процесс или поток.

Хэндл — не адрес и не «магическое число». Его нельзя разыменовать. С ним нельзя делать арифметику. Это просто «пропуск». Программа предъявляет пропуск системным функциям.

ФункцияЧто создаёт / возвращаетОшибкаЗакрывать?
CreateFileWХэндл файла (объект ядра File)INVALID_HANDLE_VALUE (−1)Да, CloseHandle
CreateEventWХэндл события (объект ядра Event)NULL (0)Да, CloseHandle
GetCurrentProcessПсевдо-хэндл текущего процесса (−1)Не бываетНет, никогда
Ключевые правила

1. Почему хэндлы малы и кратны 4. Записи таблицы хэндлов идут с шагом 4 байта. Ядро резервирует 2 младших бита под служебные флаги. Поэтому реальные хэндлы — 4, 8, 12, 16… (0x4, 0x8, 0xC, 0x10…). Хэндл — это индекс, а не адрес.

2. Псевдо-хэндл −1. GetCurrentProcess() возвращает константу ((HANDLE)(LONG_PTR)-1). Записи в таблице под неё нет. Счётчик ссылок не растёт. Функции Windows видят −1 и понимают: речь о текущем процессе. Не закрывайте его через CloseHandle. Настоящий хэндл самого себя даёт DuplicateHandle.

3. Разные коды ошибок. CreateFileW при ошибке возвращает INVALID_HANDLE_VALUE. Большинство других функций создания возвращают NULL. Среди них CreateEventW. Проверяйте именно тот код, который документирован для функции.

4. Каждый открытый хэндл надо закрыть. Незакрытые хэндлы — утечка. Объект ядра живёт, пока есть хоть один хэндл. Исключение — только псевдо-хэндлы.

5. Флаги из программы. FILE_ATTRIBUTE_TEMPORARY | FILE_FLAG_DELETE_ON_CLOSE делают файл временным. Файл удалится сам при закрытии хэндла. CREATE_ALWAYS создаёт файл заново или обнуляет существующий. TRUE в CreateEventW задаёт событие с ручным сбросом (manual-reset). FALSE задаёт начальное состояние «не сигнальное».

Типичная ошибка: Не закрывайте псевдо-хэндл (CloseHandle(GetCurrentProcess())). Не проверяйте CreateFileW на NULL вместо INVALID_HANDLE_VALUE. Вторая ошибка опасна. При неудаче CreateFileW вернёт −1. Проверка на NULL пропустит ошибку. Программа дальше будет работать с невалидным хэндлом.

Тема применяется в файле 1_lab2_word/task3_kernel_handles.cpp. Программа создаёт файл temp_kernel_demo.tmp в рабочей папке. Программа сама удаляет файл при закрытии хэндла.

Тема 5 • 2_lecture_hw/task1_pointers.cpp

Указатели и разыменование

Что это

Указатель — переменная. Она хранит адрес другой переменной в памяти. Указатель имеет тип. int* означает «адрес ячейки с целым числом». Сам указатель тоже занимает память: 4 байта в x86 и 8 байт в x64.

Не путайте три оператора. & означает «взять адрес». * в объявлении означает «это указатель». * в выражении означает «разыменовать». Разыменовать — значит обратиться к памяти по адресу.

ВыражениеЧто делаетПример
int* p;Объявляет указатель на intПеременная p хранит адрес.
p = &a;Записывает адрес переменной a в p.Теперь p указывает на a.
*p = 30;Записывает 30 в память, на которую указывает pЗначение a меняется. Указатель p не меняется.
p = &b;Перенаправляет указатель на bУказатель p меняется. Значения a и b не меняются.
int x = *p;Читает значение по адресу из pКопирует значение, на которое указывает p
Состояния памяти в лекционной задаче

Начало: a = 10, b = 20. После int* p = &a; указатель смотрит на a. После *p = 30; значения: a = 30, b = 20. После p = &b; указатель смотрит уже на b. Значения не меняются. После *p = 40; значения: a = 30, b = 40. Вывод: 30 40.

Главный вывод задачи: *p = ... меняет переменную, на которую указывает указатель. p = ... меняет сам указатель. Это две разные операции. В обеих участвует p.

Типичные ошибки: (1) Не разыменовывайте неинициализированный указатель (int* p; *p = 5;). Адрес мусорный. Программа падает. (2) Не путайте p = &b и *p = b. Первое перенаправляет указатель. Второе копирует значение. (3) Не разыменовывайте nullptr. Программа мгновенно падает с Access Violation.

Тема применяется в файлах 2_lecture_hw/task1_pointers.cpp и 1_lab2_word/task2_ptr_truncation_fix.cpp. Второй файл имеет обратный каст и разыменование *pNumber.

Тема 6 • 2_lecture_hw/task2_strings_memory.cpp

Память строк и нуль-терминатор

Что это

Строка в C — это массив символов char. Массив заканчивается невидимым символом '\0' (нуль-терминатор, код 0). Функции strlen и strcat находят конец строки по этому символу. Без '\0' строка — просто набор байтов неизвестной длины.

Строковый литерал "Hello" занимает 6 байт в памяти. Это 5 букв плюс '\0'. Компилятор добавляет нуль автоматически.

ОбъявлениеЧто создаётсяГде лежитsizeofМожно менять?
char str[] = "Hello";Массив из 6 char (копия литерала)Стек6Да, str[0] = 'h';
const char* p = "Hello";Указатель на литералУказатель лежит на стеке. Сам литерал лежит в секции констант (.rdata).8 (x64) / 4 (x86)Нет, только чтение. Запись — UB (неопределённое поведение).
Ключевые правила

1. sizeof(массив) даёт размер всего массива в байтах: 6. sizeof(указатель) даёт размер указателя: 8 в x64. Это не длина текстовой строки. Длину даёт strlen(): 5 для "Hello".

2. char str[] копирует литерал в свою память. Программа получает свою изменяемую текстовую строку. const char* p только указывает на общий неизменяемый литерал.

3. const у указателя — обещание не менять символы через него. Запись через неконстантный указатель на литерал — неопределённое поведение. Обычно программа падает, так как .rdata только для чтения.

Типичная ошибка: Не думайте, что sizeof(p) — это длина текстовой строки. Длина текстовой строки — strlen(p). sizeof(p) всегда равен 8 (x64) для любого указателя. Это верно и для строки из 5 символов, и для строки из 5000 символов.

Тема применяется в файле 2_lecture_hw/task2_strings_memory.cpp. Вывод: 6 8 в x64 и 6 4 в x86. Тема применяется также во всех задачах практики с char[].

Тема 7 • task1_vars_discount.cpp, task2_type_casting.cpp

Переменные и приведение типов

Что это

Переменная — именованная ячейка памяти с типом. Тип решает три вещи. Первое: сколько байт занимает значение. Второе: какие операции допустимы. Третье: как компилятор преобразует значение при смешивании с другими типами. int — целое (4 байта). double — вещественное двойной точности (8 байт).

Приведение типов (cast) — явное или неявное преобразование значения из одного типа в другой. Программист пишет явное приведение (static_cast<double>(a)). Компилятор делает неявное приведение сам по правилам языка.

Выражение (a = 7, b = 3)Тип операцииРезультатПочему
a / bЦелочисленное деление2 (тип int)Оба операнда имеют тип int. Деление отбрасывает дробную часть. Остаток 1 теряется.
static_cast<double>(a) / bВещественное деление2.333333… (тип double)Один операнд имеет тип double. Компилятор неявно приводит второй операнд к double.
(double)a / bТо же, C-style каст2.333333…Эквивалентно. Но static_cast виднее и безопаснее.
price * (1.0 - discount)Смешанная арифметика297.5 (тип double)Компилятор приводит int к double. Второй операнд имеет тип double.
Ключевые правила

1. Целочисленное деление отбрасывает дробь, а не округляет. 7 / 3 == 2, а не 2.33 и не 2.5. Если нужен остаток, используйте оператор % (7 % 3 == 1).

2. Достаточно привести один операнд. Один операнд деления стал double. Компилятор автоматически приводит второй операнд. Приводить оба не нужно.

3. static_cast<double>(a) лучше C-style (double)a. Каст видно в коде. Поиск находит каст. Каст не делает неожиданных низкоуровневых преобразований. reinterpret_cast делает такие преобразования.

4. Форматирование вывода. std::fixed и std::setprecision(n) из <iomanip> задают ровно n знаков после запятой. Манипуляторы «липкие». Они действуют на все следующие выводы вещественных чисел. Они не округляют сами значения. Они меняют только отображение.

5. Деньги и double. Учебные задачи допускают скидку в double. Реальные расчёты не хранят деньги в вещественных числах. 0.1 + 0.2 ≠ 0.3 из-за двоичных дробей. Храните копейки в int. Делите на 100 только при выводе.

Типичная ошибка: double x = a / b; при a = 7, b = 3 даст 2.0, а не 2.333. Деление выполняется до присваивания. Оба операнда ещё имеют тип int. Приводите операнды деления, а не его результат.

Тема применяется в файлах 3_practice_hw/task1_vars_discount.cpp и 3_practice_hw/task2_type_casting.cpp. Первый файл: сдача, скидка 15%, вывод с 2 знаками. Второй файл: деление 7/3 и вывод с 3 знаками.

Тема 8 • task3_char_reading.cpp

getchar и посимвольный ввод

Что это

getchar() (из <cstdio>) читает из стандартного ввода stdin ровно один символ. Функция возвращает его код. Это самый низкий уровень символьного ввода в C. Функция не разбирает числа или слова. Она читает только байты один за другим.

Цикл while ((ch = getchar()) != '\n' && ch != EOF) — классический идиом. Цикл читает, пока не встретится конец строки или конец ввода. Нажатие Enter даёт '\n'.

ВопросОтвет
Почему ch — int, а не char?getchar() возвращает любое значение символа (0–255) плюс особое значение EOF (обычно −1) для конца ввода. В char эти значения не помещаются одновременно. −1 совпал бы с символом 0xFF. Поэтому тип возвращаемого значения — int.
Что такое EOF?Это константа «конец файла/ввода» (обычно −1). В консоли Windows нажмите Ctrl+Z, затем Enter. В Linux/macOS нажмите Ctrl+D.
Зачем скобки вокруг присваивания?Присваивание = имеет низкий приоритет. Без скобок ch = getchar() != '\n' прочиталось бы как ch = (getchar() != '\n'). В ch попал бы 0 или 1. Скобки заставляют сначала присвоить символ, потом сравнить.
Почему символы приходят только после Enter?Консоль Windows буферизует ввод построчно. Программа получает символы, только когда пользователь нажал Enter. Это свойство терминала, а не getchar(). Для чтения клавиш без Enter используйте другие функции (_getch()).
Что делает if (ch == ' ')?Строка сравнивает код символа с кодом пробела (ASCII 32). Строка увеличивает счётчик. Табуляция ('\t') и другие пробельные символы пробелом не считаются.
Типичные ошибки: (1) Не пишите char ch; вместо int ch;. Тогда EOF (−1) неотличим от символа с кодом 255. Цикл может не завершиться или завершиться раньше времени. (2) Не забывайте скобки в while (ch = getchar() != '\n'). Без скобок присваивается результат сравнения, а не символ. (3) Не смешивайте getchar() и std::cin без синхронизации. Потоки C и C++ могут конфликтовать.

Тема 9 • task4_num_to_string.cpp, task4b_move_letter_n.cpp

sprintf, strcat и безопасность строк

Что это

В C нет встроенного типа «строка». Строка — это массив char с нулём на конце. Работа со строкой — это функции из <cstring> и <cstdio>. Две главные функции здесь: sprintf и strcat. sprintf пишет форматированный вывод в массив вместо экрана. strcat дописывает одну текстовую строку в конец другой.

ФункцияЧто делаетЧто важно знать
sprintf(buf, "%d", ID)Пишет число ID как текст в массив buf. Функция добавляет '\0'."%d" — формат десятичного целого. Результат для 245 — символы '2','4','5','\0'.
strcat(dst, src)Функция ищет '\0' в dst. Функция копирует туда src вместе с её '\0'.В dst должно быть достаточно места. Иначе произойдёт переполнение буфера.
strncat(dst, src, n)Как strcat. Но копирует не более n символов.Задача 4b копирует начало слова без буквы «н».
strstr(haystack, needle)Функция ищет подстроку. Функция возвращает указатель на неё или nullptr.Задача 4b ищет букву «н» в слове «Клиент».
strlen(s)Длина текстовой строки в байтах (без '\0').Для «н» в UTF-8 функция вернёт 2. Это байты, а не символы.
Ключевые правила

1. Запас памяти обязателен. Массив char clientStr[128] = "Клиент №"; в разы больше текстовой строки. Запас даёт место для strcat. Массив «впритык» дал бы переполнение буфера. Переполнение роняет программу или портит соседние данные.

2. _CRT_SECURE_NO_WARNINGS — до всех строк #include. MSVC считает sprintf и strcat небезопасными. MSVC выдаёт предупреждение C4996. Макрос отключает предупреждение. Строка стоит самой первой в файле. Иначе макрос не работает. В MinGW макрос ни на что не влияет.

3. Безопасные аналоги. Современный код использует snprintf вместо sprintf. Функция имеет лимит размера. Код использует strcat_s вместо strcat (MSVC). Код использует std::string и std::to_string(ID). Учебные задачи допускают старые функции. Знайте их опасность.

4. Байты ≠ символы в UTF-8. Русские буквы в UTF-8 занимают по 2 байта. Буква «н» — это байты 0xD0 0xBD. Поэтому strlen("н") == 2. Арифметика указателей (posN - clientStr) считает байты. strncat(result, clientStr, 8) копирует 4 буквы «Клие» (8 байт). Задача 4b целиком построена на этом. Программа вырезает «н» по байтовым смещениям, а не по номерам символов.

5. const char[] не меняется. В задаче 4b исходная текстовая строка имеет const. Программа собирает новую текстовую строку result. Это и есть требование задачи: исходную переменную не трогаем.

Типичные ошибки: (1) Не используйте strcat в массив без запаса. Это переполнение. (2) Не забывайте '\0' в массиве, заполненном вручную. Функции строк читают дальше по памяти. (3) Не считайте strlen числом символов для русского текста. Это байты. (4) Не используйте sprintf без проверки размера буфера. Число может не влезть. Для int достаточно 12 байт. В задачах взят запас 32.

Общий раздел

Условия запуска: компиляторы, команды, требования

Чем компилировать

MSVC (Visual Studio, Windows): Откройте «Developer Command Prompt for VS». Перейдите в папку с файлом. Соберите файл командой cl /EHsc /W4 имя.cpp. Флаг /W4 включает предупреждения. Он ловит, например, C4311 про усечение указателя. Получится имя.exe в той же папке.

MinGW-w64 (g++, Windows): Соберите файл командой g++ -Wall -Wextra -o имя.exe имя.cpp. MinGW-w64 имеет windows.h и Win32 API. Поэтому задачи 1–3 из лабы собираются и там.

Запуск: в cmd введите имя.exe. В PowerShell введите .\имя.exe. Запускайте из папки с исходником. Тогда вы увидите файлы, которые создаёт программа (задача с хэндлами).

Кодировка: Все Win32-программы лабы имеют system("chcp 65001 > nul"). Команда переключает консоль на UTF-8. Консоль показывает русский текст правильно. Сохраните исходники в UTF-8. Если консоль показывает знаки вопроса вместо букв, проверьте кодировку файла и шрифт консоли.

Что сломается, если что-то не так

— «windows.h: No such file» — задача собирается не под Windows. Или в MinGW не установлен пакет win32. Переносимые задачи (лекция, практика) собираются везде. Win32-задачи собираются только под Windows.

— Предупреждение C4996 про sprintf/strcat — в MSVC без первой строки #define _CRT_SECURE_NO_WARNINGS сборка задач 4 и 4b даст предупреждение. С флагом /WX предупреждение станет ошибкой. Макрос уже стоит в файлах. Не удаляйте его.

— Кракозябры вместо русского текста — исходник сохранён не в UTF-8. Или консоль не в UTF-8. Сохраните файл в UTF-8. Убедитесь, что выполняется chcp 65001.

— Задача 3 (хэндлы): CreateFile вернул ошибку — нет прав на запись в рабочей папке. Запустите из папки, куда разрешена запись. Например, из папки с исходником. Не запускайте из системного каталога.

— Задача 3 (getchar): программа «висит» — она ждёт ввода. Введите текст и нажмите Enter. Завершить ввод без Enter нельзя. Консоль буферизует ввод построчно.
