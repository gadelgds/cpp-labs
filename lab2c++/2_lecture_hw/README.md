## Часть 1. Разбор задач по C++ с лекции (Фото 1)

### Задача 1. Базовые операции с указателями
* **Исходный файл для копирования:** [`task1_pointers.cpp`](task1_pointers.cpp)

#### Условие
Что выведет данный фрагмент кода?
```cpp
int a = 10;
int b = 20;
int* p = &a;
*p = 30;
p = &b;
*p = 40;
std::cout << a << " " << b << std::endl;
```

#### Ответ программы
```text
30 40
```

#### Пошаговое объяснение
1. `int a = 10; int b = 20;` — в стековой памяти выделяются две ячейки: переменная `a` со значением 10 и `b` со значением 20.
2. `int* p = &a;` — создается указатель `p`, в который записывается адрес переменной `a` (указатель ссылается на `a`).
3. `*p = 30;` — оператор разыменования `*` обращается к памяти, на которую указывает `p` (то есть к `a`), и записывает туда число 30. Значения: `a = 30`, `b = 20`.
4. `p = &b;` — сам указатель `p` перенаправляется на ячейку `b`. Значение `a` не изменяется.
5. `*p = 40;` — разыменование `p` записывает число 40 в ячейку `b`. Значения: `a = 30`, `b = 40`.
6. `std::cout << a << " " << b;` — выводит итоговые значения: `30 40`.

### Задача 2. Строки и массивы в памяти
* **Исходный файл для копирования:** [`task2_strings_memory.cpp`](task2_strings_memory.cpp)

#### Условие
Что выведет программа? Чему равен `sizeof(str)` и `sizeof(p)` в 64-битной системе?
```cpp
char str[] = "Hello";
const char* p = "Hello";
std::cout << sizeof(str) << " " << sizeof(p) << std::endl;
```

#### Ответ программы (в x64 системе)
```text
6 8
```
*(Для сравнения: в 32-битной системе вывод был бы: `6 4`)*.

#### Пошаговое объяснение
1. `sizeof(str) == 6 байт`:
   * `char str[] = "Hello";` создает локальный символьный массив фиксированного размера на стеке.
   * Строковый литерал `"Hello"` состоит из 5 видимых символов (`'H'`, `'e'`, `'l'`, `'l'`, `'o'`) плюс обязательный невидимый завершающий нуль-терминатор `'\0'`.
   * Каждый элемент типа `char` занимает ровно 1 байт.
   * Итого полный размер массива в памяти: $5 + 1 = 6$ байт.
2. `sizeof(p) == 8 байт`:
   * `const char* p = "Hello";` создает переменную-указатель.
   * Литерал `"Hello"` помещается компилятором в неизменяемую секцию константных данных (`.rdata`), а переменная `p` хранит только адрес первого байта.
   * Оператор `sizeof(p)` возвращает размер **самой переменной-указателя**, а не строки!
   * В 64-битной архитектуре (x64) размер любого указателя в адресном пространстве составляет 8 байт (64 бита). Длина самой строки вычисляется функцией `strlen(p)` и равна 5.

## Часть 2. Ответы на 6 экзаменационных вопросов по ОС и Win32 (Фото 3)

### Вопрос 1
> **Что произойдет, если запустить ReadFile асинхронно, но сразу же закрыть хэндл файла через CloseHandle, не дожидаясь окончания операции?**

**Ответ:**
1. **Поведение объекта ядра:** Вызов `ReadFile` с флагом `OVERLAPPED` отправляет запрос драйверу диска (создается структура `IRP` — I/O Request Packet). Драйвер удерживает собственную ссылку на объект файла (`File Object`). При вызове `CloseHandle(hFile)` дескриптор удаляется из таблицы процесса, а счетчик ссылок уменьшается, но сам объект файла не уничтожится немедленно, пока активен IRP.
2. **Отмена ввода-вывода:** Закрытие хэндла обычно отправляет драйверу команду `IRP_MJ_CLEANUP`, инициируя попытку отмены асинхронной операции (I/O Cancellation).
3. **Критическая опасность порчи памяти:** Если буфер для данных (`lpBuffer`) или структура `OVERLAPPED` были выделены локально на стеке функции, то поток выйдет из нее, стек будет перезаписан, а драйвер/контроллер DMA позже попытается записать прочитанные с диска данные по старому адресу. Это приведет к порче памяти (**Memory Corruption**) или аварийному завершению (**BSOD / Access Violation**).
4. **Невозможность проверить результат:** Функция `GetOverlappedResult` вернет ошибку `ERROR_INVALID_HANDLE`, так как дескриптор закрыт.

### Вопрос 2
> **Почему для структуры OVERLAPPED критически важно обнулять её поля (например, через `= {0}` или `memset`) перед передачей в системный вызов?**

**Ответ:**
Структура `OVERLAPPED` содержит поля смещения (`Offset`, `OffsetHigh`) и дескриптор события (`hEvent`). Если структура не инициализирована, она заполнена случайными "мусорными" байтами из стека:
1. **Файловое смещение (`Offset`, `OffsetHigh`):** В асинхронном режиме Windows не обновляет скрытый файловый указатель. Смещение, откуда читать или куда писать, ядро считывает исключительно из этих полей. Мусорные байты заставят ядро пытаться читать файл с гигантского адреса (например, 2 терабайта), что приведет к ошибке выхода за границы файла (`ERROR_HANDLE_EOF`) или порче данных.
2. **Хэндл события (`hEvent`):** Ядро проверяет, не равен ли `hEvent` нулю. При наличии мусора ядро примет случайное число за валидный дескриптор события и попытается вызвать `SetEvent()`, что приведет к ложному срабатыванию или ошибке.

### Вопрос 3
> **Маленький файл (10 байт) сохранен в NTFS как резидентный. Будет ли при его чтении через ReadFile с флагом OVERLAPPED происходить реальная асинхронная задержка ввода-вывода?**

**Ответ:**
**Нет, реальной асинхронной задержки ввода-вывода не будет.**
* В файловой системе NTFS файлы размером до ~700–800 байт сохраняются прямо внутри 1024-байтной записи таблицы MFT (Master File Table) в виде так называемого **резидентного атрибута** `$DATA` (Resident Attribute).
* При открытии файла запись MFT уже находится в кэше метаданных оперативной памяти ядра.
* Драйверу NTFS не требуется посылать команды физическому контроллеру накопителя, перемещать головки HDD или ждать ответа контроллера SSD.
* `ReadFile` мгновенно копирует 10 байт из памяти MFT в буфер приложения и синхронно возвращает `TRUE` (без перехода в состояние ожидания `ERROR_IO_PENDING`).

### Вопрос 4
> **Как можно открыть файлы с именем $MFT?**

**Ответ:**
`$MFT` — это закрытый системный метафайл NTFS (Master File Table). Прямой вызов `CreateFileW(L"C:\\$MFT", ...)` блокируется драйвером файловой системы и возвращает `ERROR_ACCESS_DENIED`.
**Способы получить доступ:**
1. **Прямой низкоуровневый доступ к тому (Raw Volume Access):** Запустить программу с правами Администратора и открыть том как блочное устройство:
   ```cpp
   HANDLE hVol = CreateFileW(L"\\\\.\\C:", GENERIC_READ, FILE_SHARE_READ | FILE_SHARE_WRITE, NULL, OPEN_EXISTING, 0, NULL);
   ```
   Затем через вызов `DeviceIoControl()` с кодами `FSCTL_GET_NTFS_FILE_RECORD` или `FSCTL_GET_RETRIEVAL_POINTERS` можно напрямую считывать сырые записи MFT.
2. **Использование USN Journal:** Официальный Win32 API для отслеживания изменений файлов `FSCTL_READ_USN_JOURNAL`, читающий метаданные MFT легальным системным способом.
3. **Через теневые копии тома (VSS):** В моментальных снимках Volume Shadow Copy драйвер иногда разрешает прямое побайтовое чтение файла `$MFT`.

### Вопрос 5
> **Почему в Windows файлы ИМЯ.txt и имя.txt — это один и тот же файл?**

**Ответ:**
1. **Поведение подсистемы Win32:** Исторически со времен MS-DOS среда Windows проектировалась как регистронезависимая (**Case-Insensitive**) для удобства пользователя. Пользовательские вызовы API (`CreateFile`, `FindFirstFile`) из `kernel32.dll` всегда передают в ядро флаг `OBJ_CASE_INSENSITIVE` и приводят символы к верхнему регистру по системной таблице Unicode.
2. **Возможности ядра NT и NTFS:** Само ядро Windows NT и файловая система NTFS **поддерживают регистрозависимость** (Case-Sensitive Capable) и сохраняют исходный регистр букв для отображения (Case-Preserving). При прямом вызове Native API (`NtCreateFile`) без флага `OBJ_CASE_INSENSITIVE` файлы `ИМЯ.txt` и `имя.txt` могут быть двумя разными файлами в одном каталоге (это используется, например, в подсистеме WSL).
3. В Windows 10/11 для конкретной папки регистрозависимость можно включить вручную: `fsutil.exe file setCaseSensitiveInfo <папка> enable`.

### Вопрос 6
> **Как ОС узнает свободен ли сектор на диске?**

**Ответ:**
1. **Файловая система оперирует кластерами:** Сектор (512 байт или 4 КБ) — это физическая единица диска, а файловая система выделяет место блоками кластеров (обычно 4 КБ = группа секторов).
2. **Битовая карта тома `$Bitmap` в NTFS:** В NTFS в корне каждого тома существует специальный системный метафайл `$Bitmap` (запись 6 в таблице MFT). Он представляет собой огромный битовый массив:
   * **Бит = 0:** кластер свободен для записи нового файла;
   * **Бит = 1:** кластер занят данными или метаданными.
   При записи файла драйвер NTFS находит в `$Bitmap` непрерывную цепочку нулевых бит и устанавливает их в 1.
3. **Таблица FAT в FAT32:** В FAT-системах статус хранится в File Allocation Table (свободный кластер помечен значением `0x00000000`).
4. **Уровень SSD (команда TRIM):** Для SSD-накопителей операционная система отправляет контроллеру команду **TRIM** (SATA) или **Deallocate** (NVMe), уведомляя контроллер о том, что соответствующие физические страницы памяти больше не нужны и могут быть стёрты фоновым сборщиком мусора.
