Примечание: в задании написано «DWORD_ptr» — правильное имя типа DWORD_PTR (заглавные буквы, т.к. это макрос).

Почему так — суть модели данных

1. В Windows x64 используется модель LLP64: int и long остаются 32-битными (по 4 байта), чтобы старый 32-битный код продолжал работать без переделки. Именно поэтому long НЕ стал 8 байт (в отличие от Linux, где модель LP64).

2. Указатель (void*) в x64 обязан вырасти до 8 байт — адресное пространство стало 64-битным, любой адрес занимает 64 бита.

3. Типы *_PTR (ULONG_PTR, DWORD_PTR, INT_PTR) — это «целые размером с указатель». Компилятор выбирает их ширину под архитектуру: 4 байта в x86, 8 байт в x64. Их специально придумали, чтобы хранить адреса без усечения.

Задача 3. Усечение указателя: находим и исправляем

1) Ошибочный (исходный) код — как в задании
до исправления
было (с ошибкой) 
void ProcessData(DWORD dataStylePointer) {
    int* pNumber = (int*)dataStylePointer;
    if (pNumber != nullptr) {
        std::cout << "Value: " << *pNumber << std::endl;
    }
}

int main() {
    int criticalValue = 2026;
    int* lpContext = &criticalValue;

    DWORD TRUNCATED_PTR = (DWORD)lpContext;
    ProcessData(TRUNCATED_PTR);

    return 0;
}
Что сказал компилятор в x64 (реально):
warning C4311: приведение типов: усечение указателя из "int *" в "DWORD"
warning C4312: приведение типов: преобразование из "DWORD" в "int *" большего размера
warning C4302: приведение типов: усечение из "int *" к "DWORD"
Что произошло при запуске x64: программа упала с кодом -1073741819 = 0xC0000005 — это Access Violation (обращение к недопустимой памяти).
В x86: тот же код работает и печатает Value: 2026, потому что там указатель и так 4 байта.
В чём именно ошибка

DWORD — это 32 бита (4 байта). В x64 указатель занимает 8 байт. Приведение (DWORD)lpContext отбрасывает старшие 32 бита адреса. В ProcessData из этого «обрезанного» числа снова делают указатель — адрес получается битым, и разыменование *pNumber (чтение памяти по этому адресу) роняет процесс.

2) Исправленное решение (чистое, без комментариев)

#include <windows.h>
#include <iostream>

void ProcessData(DWORD_PTR dataStylePointer) {
    int* pNumber = reinterpret_cast<int*>(dataStylePointer);
    if (pNumber != nullptr) {
        std::cout << "Value: " << *pNumber << std::endl;
    }
}

int main() {
    #if defined(_WIN32)
    system("chcp 65001 > nul");
    #endif

    int criticalValue = 2026;
    int* lpContext = &criticalValue;

    DWORD_PTR SAFE_PTR = (DWORD_PTR)lpContext;

    ProcessData(SAFE_PTR);

    return 0;
}
x86 → Value: 2026 x64 → Value: 2026 (собрано /W3 — без предупреждений)

Задача 4 · Хэндлы ядра

Задача 4. Три хэндла объектов ядра Windows

Чистое решение (без комментариев)
task3_kernel_handles.cpp
task3_kernel_handles.cpp · без комментариев 
#include <windows.h>
#include <iostream>

int main() {
    #if defined(_WIN32)
    system("chcp 65001 > nul");
    #endif

    HANDLE hFile = CreateFileW(
        L"temp_kernel_demo.tmp",
        GENERIC_READ | GENERIC_WRITE,
        FILE_SHARE_READ,
        NULL,
        CREATE_ALWAYS,
        FILE_ATTRIBUTE_TEMPORARY | FILE_FLAG_DELETE_ON_CLOSE,
        NULL
    );

    HANDLE hEvent = CreateEventW(NULL, TRUE, FALSE, NULL);

    HANDLE hProcess = GetCurrentProcess();

    std::cout << "=== Объекты ядра Windows и их дескрипторы ===" << std::endl;
    std::cout << "1. File Handle (CreateFile):             " << (void*)hFile    << " (UINT_PTR: " << (UINT_PTR)hFile    << ")" << std::endl;
    std::cout << "2. Event Handle (CreateEvent):           " << (void*)hEvent   << " (UINT_PTR: " << (UINT_PTR)hEvent   << ")" << std::endl;
    std::cout << "3. Current Process (GetCurrentProcess):  " << (void*)hProcess << " (UINT_PTR: " << (UINT_PTR)hProcess << ")" << std::endl;

    if (hFile != INVALID_HANDLE_VALUE) {
        CloseHandle(hFile);
    }
    if (hEvent != NULL) {
        CloseHandle(hEvent);
    }

    return 0;
}

Ответы на вопросы задания

1. Почему хэндлы малы и кратны 4?

  • Хэндл — это не адрес, а индекс (смещение) в таблице дескрипторов процесса (Process Handle Table).
  • Записи в таблице идут с шагом, кратным 4 байтам, а младшие 2 бита зарезервированы ядром под служебные флаги. Отсюда значения 4, 8, 12, 16, …
  • В выводе видно ровно это: 0xC0 = 192, 0xBC = 188 — оба делятся на 4.
  • В x64 хэндлы всё равно остаются 32-битными числами (≈4 млрд возможных значений) — старшие 32 бита нулевые, поэтому значение выглядит «маленьким».

2. Почему GetCurrentProcess возвращает −1 (0xFFFFFFFF)?

  • Это псевдо-дескриптор — заранее заданная константа, а не реальная запись в таблице.
  • Функции ядра «знают» это значение и молча подставляют текущий процесс — так быстрее, чем открывать настоящий хэндл.
  • В x86 это 0xFFFFFFFF (4294967295), в x64 — 0xFFFFFFFFFFFFFFFF (18446744073709551615), т.е. все биты в единицу.
  • Есть и другие псевдо-хэндлы: GetCurrentThread() = −2, GetCurrentProcess() = −1. Закрывать их через CloseHandle нельзя.
Доп. задача · Буква «н» + число

Задача про «Клиент»: переставить букву «н» в начало и дописать число

Взять «н», поставить в начало, убрать из середины, добавить число
task4b_move_letter_n.cpp

Из слова «Клиент» берём букву н, не изменяя исходную переменную, ставим её в начало, затем дописываем «Клиент» уже без этой н, и в конце — число. Получается нКлиет245.

task4b_move_letter_n.cpp · без комментариев 
#define _CRT_SECURE_NO_WARNINGS
#include <iostream>
#include <cstdio>
#include <cstring>

int main() {
    #if defined(_WIN32)
    system("chcp 65001 > nul");
    #endif

    const char clientStr[] = "Клиент";
    int ID = 245;

    char idStr[32];
    sprintf(idStr, "%d", ID);

    const char letterN[] = "н";

    char result[128] = "";

    strcat(result, letterN);

    const char* posN = strstr(clientStr, letterN);
    if (posN != nullptr) {
        int before = (int)(posN - clientStr);
        strncat(result, clientStr, before);
        strcat(result, posN + strlen(letterN));
    }

    strcat(result, idStr);

    std::cout << "Исходная строка (не изменена): " << clientStr << std::endl;
    std::cout << "Результат:                     " << result << std::endl;

    return 0;
}
Исходная строка (не изменена): Клиент Результат: нКлиет245
