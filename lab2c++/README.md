## 1. Задания из файла Word

### Задание 1. Префиксы венгерской нотации и типы данных Win32
- **`LPCSTR pszName`**:
  - `psz`: `p` (pointer / указатель), `sz` (string zero-terminated / строка с `\0`).
  - `LPCSTR`: Long Pointer to Constant STRing.
  - Реальный тип C/C++: **`const char*`**.
- **`LPVOID lpBuffer`**:
  - `lp`: `l` (long), `p` (pointer).
  - `LPVOID`: Long Pointer to VOID.
  - Реальный тип C/C++: **`void*`**.
- **`HMODULE hMod`**:
  - `h`: handle (дескриптор).
  - `HMODULE`: Handle to a Module (базовый адрес загрузки `.exe` или `.dll` в виртуальном пространстве).
  - Реальный тип C/C++: **`HINSTANCE` / `HANDLE` / `void*`**.
- **`DWORD cbSize`**:
  - `cb`: count of bytes (количество байт).
  - `DWORD`: Double Word (двойное слово = 32 бита).
  - Реальный тип C/C++: **`unsigned long`** (32-битное беззнаковое целое число).

### Задание 2. Исследование моделей памяти (x86 vs x64)
Сводная таблица размеров типов:

| Тип данных | Архитектура x86 (32-бит) | Архитектура x64 (64-бит) | Причина различия / Модель |
| :--- | :---: | :---: | :--- |
| `int` | 4 байта | 4 байта | Базовый integer |
| `long` | 4 байта | 4 байта | В Windows модель LLP64: `long` всегда 32 бита |
| `long long` | 8 байт | 8 байт | 64-битное целое число |
| `void*` | 4 байта | **8 байт** | Адрес памяти в 64-битном адресном пространстве |
| `DWORD` | 4 байта | 4 байта | `unsigned long` — фиксированный 32-битный тип |
| `LONG` | 4 байта | 4 байта | `long` — фиксированный 32-битный тип |
| `ULONG_PTR` | 4 байта | **8 байт** | Полиморфное беззнаковое целое точности указателя |
| `DWORD_PTR` | 4 байта | **8 байт** | Полиморфный целочисленный тип для адресов |
| `INT_PTR` | 4 байта | **8 байт** | Полиморфное знаковое целое точности указателя |

**Объяснение**: В Windows x64 применяется модель **LLP64**, чтобы не ломать старый 32-битный код: типы `int` и `long` сохраняют размер 4 байта, а размер меняют только указатели и полиморфные типы с суффиксом `_PTR`.

### Задание 3. Ошибка усечения указателя (Pointer Truncation)
В коде:
```cpp
DWORD TRUNCATED_PTR = (DWORD)lpContext;
ProcessData(TRUNCATED_PTR);
```
- **В x86**: Указатель 32 бита и `DWORD` 32 бита — потерь нет.
- **В x64**: Указатель 64 бита (8 байт), а `DWORD` — всего 32 бита (4 байта). Старшие 32 бита адреса безвозвратно теряются. При касте обратно в указатель получается невалидный адрес, и разыменование `*pNumber` приводит к критической ошибке `Access Violation (0xC0000005)`.
- **Решение**: Использовать `DWORD_PTR` вместо `DWORD` как в типе аргумента функции, так и при приведении переменной.

### Задание 4. Объекты ядра Windows и псевдо-дескрипторы
1. **Почему хэндлы кратны 4 и малы?**
   Хэндл в Windows — это не прямой указатель на память ядра, а индекс (смещение) в таблице дескрипторов процесса (Process Handle Table). Записи в таблице имеют смещение с шагом 4 байта, а младшие 2 бита зарезервированы ядром под служебные флаги (например, защиту дескриптора от закрытия).
2. **Почему `GetCurrentProcess()` возвращает `-1` (`0xFFFFFFFF`)?**
   Это системная константа (псевдо-хэндл). Она не занимает место в таблице дескрипторов процесса и служит быстрым указателем на самого себя. Закрывать ее через `CloseHandle()` не требуется.

## 2. Экзаменационные вопросы по ОС и файловым системам (Фото 3)

1. **Что произойдет, если запустить ReadFile асинхронно, но сразу же закрыть хэндл файла через CloseHandle, не дожидаясь окончания операции?**
   - Ядро Windows уменьшит счетчик ссылок на объект файла, но драйвер накопителя держит собственную ссылку на File Object в активном IRP, поэтому объект ядра сразу не уничтожится.
   - Закрытие хэндла инициирует процедуру очистки (`IRP_MJ_CLEANUP`) и отмену операции ввода-вывода.
   - Главная опасность: если переданный буфер памяти находился на стеке или был освобожден, драйвер или DMA-контроллер запишет данные по освобожденному адресу, вызвав повреждение памяти. Функция `GetOverlappedResult` вернет `ERROR_INVALID_HANDLE`.
2. **Почему для структуры OVERLAPPED критически важно обнулять её поля перед передачей в системный вызов?**
   - Неинициализированная структура содержит случайный стек-мусор. Поля `Offset` и `OffsetHigh` задают файловое смещение: мусор приведет к чтению за пределами файла (`ERROR_HANDLE_EOF`). Поле `hEvent` при наличии мусора ядро примет за валидный хэндл и попытается вызвать для него `SetEvent()`.
3. **Маленький файл (10 байт) сохранен в NTFS как резидентный. Будет ли при его чтении через ReadFile с флагом OVERLAPPED происходить реальная асинхронная задержка ввода-вывода?**
   - **Нет**, реальной асинхронной задержки не будет. Резидентный файл хранится прямо внутри записи MFT, которая уже загружена в память ядра. Функция `ReadFile` синхронно и мгновенно скопирует данные в буфер и вернет `TRUE`.
4. **Как можно открыть файлы с именем $MFT?**
   - Прямой путь `C:\$MFT` запрещен драйвером NTFS (`ERROR_ACCESS_DENIED`).
   - Доступ возможен: через открытие физического тома с правами Администратора (`CreateFileW(L"\\\\.\\C:", ...)`) и вызов `DeviceIoControl` с кодом `FSCTL_GET_NTFS_FILE_RECORD`, либо через USN Journal (`FSCTL_READ_USN_JOURNAL`), либо из теневой копии тома (VSS).
5. **Почему в Windows файлы ИМЯ.txt и имя.txt — это один и тот же файл?**
   - Подсистема Win32 API исторически регистронезависима (Case-Insensitive) для совместимости с MS-DOS. При вызове Win32 функций всегда передается системный флаг ядра `OBJ_CASE_INSENSITIVE`, а имена нормализуются переводом в верхний регистр. Сама NTFS при этом сохраняет исходный регистр для отображения (Case-Preserving).
6. **Как ОС узнает свободен ли сектор на диске?**
   - ОС работает на уровне кластеров. В файловой системе NTFS для этого служит метафайл **`$Bitmap`** (запись 6 MFT) — массив бит, где бит 0 означает свободный кластер, а 1 — занятый. Для SSD дисков ОС дополнительно передает контроллеру команду **TRIM** (ATA) или **Deallocate** (NVMe).
