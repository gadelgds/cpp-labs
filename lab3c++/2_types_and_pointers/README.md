# Раздел 2. Типы данных, универсальные указатели `void*` и проецирование памяти со смещением

В этом разделе подробно разобраны задачи на явное приведение типов в C++, работу с универсальными указателями `void*` в 64-битной архитектуре и выравнивание смещений в системных вызовах Windows API `MapViewOfFile`.

---

## Задача 1. Явное приведение типов через `static_cast` (Блок «Наизусть 72»)

* **Исходный файл:** [`task1_explicit_casting.cpp`](task1_explicit_casting.cpp)

### Условие
Создайте новую переменную типа `long`, в которую запишите результат вычитания переменной `int` из переменной `long`. Перед выполнением вычитания, значение переменной `int` должно быть явно приведено к типу `long` с помощью `static_cast<long>()` (то же самое с `float` и `double`).

### Подробный построчный разбор программы

#### 1. Вычитание целых чисел с явным приведением
```cpp
long valLong = 100000L;
int valInt = 25000;

long resultLong = valLong - static_cast<long>(valInt);
```
* `long valLong = 100000L;` — объявление переменной типа `long` с суффиксом `L` (32 бита в Windows).
* `int valInt = 25000;` — переменная базового целочисленного типа `int` (32 бита).
* `static_cast<long>(valInt)` — **явное приведение типов времени компиляции (Compile-time Type Cast)** стандарта C++. Компилятор проверяет допустимость преобразования типов на этапе трансляции, исключая неоднозначности.
* `valLong - static_cast<long>(valInt)` — вычитание двух операндов одинакового типа `long`. Результат помещается в `resultLong`.

#### 2. Вычитание чисел с плавающей точкой
```cpp
double valDouble = 125.75;
float valFloat = 25.25f;

double resultDouble = valDouble - static_cast<double>(valFloat);
```
* `double valDouble = 125.75;` — 64-битное вещественное число двойной точности (IEEE 754 Double Precision, 53 бита мантиссы).
* `float valFloat = 25.25f;` — 32-битное вещественное число одинарной точности (IEEE 754 Single Precision, 24 бита мантиссы).
* `static_cast<double>(valFloat)` — расширяющее явное приведение 32-битного числа `float` к 64-битному представлению `double`.
* `resultDouble` — сохраняет точный результат вещественного вычитания `100.5000`.

## Задача 2. Универсальные указатели `void*` и разрядность x64 (Блок «Самостоятельно»)

* **Исходный файл:** [`task2_void_pointers_x64.cpp`](task2_void_pointers_x64.cpp)

### Условие
Создайте переменную типа `int`/`long`. Инициализируйте их любыми произвольными значениями.
Создайте независимый универсальный указатель типа `void*`. Запишите в них адрес созданной переменной.
Преобразуйте указатели `void*` обратно в исходный тип `int*`/`long*`/`long long*`. Извлеките значения из памяти и выведите их на экран. Определить размер указателя и переменных в х64.

### Подробный построчный разбор программы

#### 1. Создание переменных и взятие адреса в `void*`
```cpp
int numInt = 42;
long numLong = 123456L;

void* ptrVoid1 = &numInt;
void* ptrVoid2 = &numLong;
```
* `int numInt = 42;` — целочисленная переменная на стеке.
* `&numInt` — оператор взятия адреса памяти.
* `void* ptrVoid1 = &numInt;` — нетипизированный (универсальный) указатель. В C++ тип `void*` может принимать адрес объекта любого типа без явного приведения. Однако `void*` **нельзя разыменовать** напрямую (`*ptrVoid1` вызовет ошибку компиляции), так как компилятору неизвестен размер типа и способ интерпретации байтов.

#### 2. Обратное приведение и разыменование
```cpp
int* ptrInt = static_cast<int*>(ptrVoid1);
long* ptrLong = static_cast<long*>(ptrVoid2);

std::cout << *ptrInt << std::endl;
std::cout << *ptrLong << std::endl;
```
* `static_cast<int*>(ptrVoid1)` — безопасное явное обратное преобразование `void*` в типизированный указатель `int*`.
* `*ptrInt` — оператор разыменования: считывает 4 байта из ячейки памяти по адресу `ptrInt` и интерпретирует их как целое число со знаком (`42`).

#### 3. Размеры в архитектуре x64
```cpp
sizeof(void*)      // 8 байт (64 бита)
sizeof(int*)       // 8 байт (64 бита)
sizeof(long*)      // 8 байт (64 бита)
sizeof(int)        // 4 байта (32 бита)
sizeof(long)       // 4 байта (32 бита в Windows LLP64)
sizeof(long long)  // 8 байт (64 бита)
```
* **Ключевой вывод:** в 64-битной архитектуре x64 **любой указатель** (`void*`, `int*`, `char*`) занимает ровно **8 байт**, независимо от того, на тип какого размера он ссылается!

## Задача 3. Проецирование файла с фиксированным смещением (`MapViewOfFile`)

* **Исходный файл:** [`task3_memory_mapped_offset.cpp`](task3_memory_mapped_offset.cpp)

### Условие
Напишите программу, которая имитирует чтение огромного файла порциями. Программа должна спроецировать текстовый файл, но вызвать `MapViewOfFile` так, чтобы отобразить не начало файла, а строго его кусок, находящийся на определенном смещении. Смещение (параметры `dwFileOffsetHigh` и `dwFileOffsetLow` в `MapViewOfFile`) **не может быть случайным**.

### Почему смещение в `MapViewOfFile` не может быть произвольным?
В архитектуре подсистемы виртуальной памяти Windows (Virtual Memory Manager) отображение страниц файла в адресное пространство процесса привязано к аппаратному блоку управления памятью (MMU) процессора.
* Системная гранулярность выделения памяти (**Allocation Granularity**) в Windows для архитектур x86 и x64 составляет **64 КБ (65 536 байт)**.
* Если передать в `MapViewOfFile` смещение, не кратное 64 КБ (например, 1000 байт), функция завершится с ошибкой **`ERROR_MAPPED_ALIGNMENT` (код 1132)**: *"Базовый адрес или смещение файла для указанного представления не имеют требуемого выравнивания"*.

### Построчный разбор реализации
```cpp
// 1. Получаем гранулярность от ядра Windows
SYSTEM_INFO sysInfo;
GetSystemInfo(&sysInfo);
DWORD allocGranularity = sysInfo.dwAllocationGranularity; // 65536 байт

// 2. Создаем файл и объект проецирования
HANDLE hFile = CreateFileW(filename, GENERIC_READ | GENERIC_WRITE, ...);
HANDLE hMapping = CreateFileMappingW(hFile, NULL, PAGE_READONLY, 0, 0, NULL);

// 3. Вычисляем смещение строго кратное allocGranularity
size_t targetOffset = 2 * allocGranularity; // 131 072 байт (128 КБ)
DWORD offsetLow = (DWORD)(targetOffset & 0xFFFFFFFF);
DWORD offsetHigh = (DWORD)((targetOffset >> 32) & 0xFFFFFFFF);
SIZE_T viewSize = 1024; // Размер окна = 1 КБ

// 4. Проецируем срез файла в память
const char* pView = static_cast<const char*>(MapViewOfFile(
    hMapping,
    FILE_MAP_READ,
    offsetHigh,
    offsetLow,
    viewSize
));

// 5. Читаем данные напрямую по указателю памяти
std::string readChunk(pView, 35);

// 6. Размонтируем отображение
UnmapViewOfFile(pView);
```
1. `GetSystemInfo(&sysInfo)` — опрашивает параметры процессора и диспетчера памяти ОС.
2. `CreateFileMappingW(hFile, NULL, PAGE_READONLY, 0, 0, NULL)` — создает объект "секция" ядра Windows, связывающий физический файл со страницами виртуальной памяти.
3. `targetOffset = 2 * allocGranularity;` — гарантирует строгое выравнивание смещения на границу 64 КБ.
4. `MapViewOfFile(hMapping, FILE_MAP_READ, offsetHigh, offsetLow, viewSize)` — выделяет диапазон страниц в виртуальном адресном пространстве процесса и отображает указанный 1 КБ фрагмент файла по полученному смещению 128 КБ.
5. `UnmapViewOfFile(pView)` — освобождает виртуальные адреса и удаляет запись из таблицы страниц процесса.
