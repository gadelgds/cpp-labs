# Лабораторная работа №3: Асинхронный ввод-вывод и устройство файловой системы NTFS (MFT)

### Задача 1. Асинхронное копирование большого файла с `OVERLAPPED` и `hEvent`

* **Исходный файл для копирования:** [`task1_async_copy_overlapped.cpp`](task1_async_copy_overlapped.cpp)

#### Условие
Написать консольное приложение на C++, копирующее файл большого объема (от 1 ГБ) блоками фиксированного размера (например, 64 КБ) с использованием `FILE_FLAG_OVERLAPPED` и событий (`hEvent`).

#### Построчный разбор основных блоков:
1. `const DWORD CHUNK_SIZE = 64 * 1024;` — задает размер буфера порции передачи (65 536 байт = 64 КБ). Это стандартный размер аппаратного блока для контроллеров дисков и гранулярности распределения памяти Windows (`Allocation Granularity`).
2. `CreateDummyFile(srcPath, 1024);` — быстрая генерация тестового файла на 1 ГБ через вызовы `SetFilePointerEx(hFile, 1GB, ...)` и `SetEndOfFile(hFile)`. Это мгновенно выделяет логический размер файла без необходимости долгой побайтовой записи.
3. `CreateFileW(..., FILE_FLAG_OVERLAPPED, ...);` — **главный системный флаг**. Сообщает ядру Windows, что функции `ReadFile` и `WriteFile` должны выполняться в неблокирующем режиме: вызов возвращает управление немедленно, а передача данных в память выполняется контроллером диска в фоне по DMA.
4. `HANDLE hReadEvent = CreateEventW(NULL, TRUE, FALSE, NULL);` — создает объект синхронизации ядра Windows (событие с ручным сбросом `Manual-Reset Event`). Когда контроллер накопителя завершает чтение, драйвер переводит данное событие в сигнальное состояние.
5. `memset(&ovRead, 0, sizeof(ovRead));` — **обнуление структуры `OVERLAPPED`**. Критически важная операция: мусор со стека в полях смещения приведет к сбою или чтению с некорректного адреса.
6. `ovRead.Offset = (DWORD)(currentOffset & 0xFFFFFFFF); ovRead.OffsetHigh = (DWORD)(currentOffset >> 32);` — в асинхронном режиме скрытый указатель файла не используется, поэтому точное 64-битное смещение блока обязано явно передаваться в структуру для каждого пакета.
7. `ReadFile(hSrc, buffer, bytesToRead, NULL, &ovRead);` — инициирует асинхронное чтение. Возвращает `FALSE`, а код `GetLastError()` равен `ERROR_IO_PENDING (997)` (операция отложена и выполняется драйвером в фоне).
8. `WaitForSingleObject(hReadEvent, INFINITE);` — переводит поток в энергоэффективный режим ожидания аппаратного прерывания (нагрузка на CPU = 0%).
9. `GetOverlappedResult(hSrc, &ovRead, &bytesTransferred, FALSE);` — опрашивает ядро о фактическом количестве переданных байт и статусе завершения пакета.
10. `WriteFile(hDst, buffer, bytesTransferred, NULL, &ovWrite);` — асинхронная запись данных на диск по аналогичной схеме с контролем через `hWriteEvent`.

### Задача 2. Умение читать MFT файл (резидентные и нерезидентные данные)

* **Исходный файл для копирования:** [`task2_mft_resident_theory.cpp`](task2_mft_resident_theory.cpp)

#### Условие
Умение читать MFT файл при условии, что на диске размер одного и того же файла в одном случае строго меньше 500 КБ, в другом больше 2000.

#### Теоретический и построчный разбор:
1. **Структура записи MFT:** Главная таблица файлов NTFS состоит из записей фиксированного размера **1024 байта (1 КБ)**. Каждая запись содержит заголовок и цепочку атрибутов (`$STANDARD_INFORMATION`, `$FILE_NAME`, `$DATA`).
2. **Резидентный атрибут (`$DATA Resident`):** Если размер содержимого файла меньше примерно 700–800 байт (например, 200 байт), данные файла сохраняются непосредственно внутри самой 1024-байтной записи MFT. Кластеры дискового тома под такой файл не выделяются, физический размер вне MFT равен 0 байт.
3. **Нерезидентный атрибут (`$DATA Non-Resident`):** Если размер файла превышает свободное место в MFT-записи (например, 2000 байт или 500 КБ), данные не помещаются в 1 КБ. Файловая система выделяет отдельные физические кластеры на диске, а внутри MFT сохраняет так называемые `Data Runs` (цепочки номеров физических кластеров LCN и виртуальных номеров VCN).
4. `DeviceIoControl(hFile, FSCTL_GET_RETRIEVAL_POINTERS, ...)` — опрашивает драйвер файловой системы о карте кластеров файла:
   * Для резидентного файла вызов завершается с ошибкой `ERROR_HANDLE_EOF (код 38)` — у файла нет внешних экстентов, так как он лежит в MFT.
   * Для нерезидентного файла вызов возвращает `TRUE` и заполняет структуру `RETRIEVAL_POINTERS_BUFFER`, в которой перечислены количество экстентов (`ExtentCount`) и физические номера кластеров (`Lcn`).

### Задача 3. Физический размер файла вне таблицы MFT (`GetCompressedFileSize`)

* **Исходный файл для копирования:** [`task3_mft_physical_size.cpp`](task3_mft_physical_size.cpp)

#### Условие
Написать небольшую утилиту, которая создает два файла с разным объемом текстовых данных, а затем опрашивает файловую систему о том, сколько реальных физических байт эти файлы заняли на жестком диске вне таблицы MFT:
* **Кейс 1 (Маленький файл):** Размер содержимого — строго 200 байт.
* **Кейс 2 (Большой файл):** Размер содержимого — строго 2000 байт (чуть меньше 2 КБ).

#### Построчный разбор функции `investigateFile`:
1. `CreateFileW(fileName, GENERIC_WRITE, ...);` — создание файла с флагом `CREATE_ALWAYS`.
2. `char* buffer = new char[bytesToWrite]; memset(buffer, 'A', bytesToWrite);` — выделение буфера нужного размера и заполнение тестовыми символами.
3. `WriteFile(hFile, buffer, bytesToWrite, &bytesWritten, NULL);` — запись данных в файл.
4. `CloseHandle(hFile);` — закрытие дескриптора для сброса файлового буфера и сохранения метаданных NTFS.
5. `DWORD physicalSize = GetCompressedFileSizeW(fileName, &highSize);` — системный вызов Win32 API, возвращающий реальный объем дискового пространства, выделенного файловой системой под данный файл вне MFT.
6. **Анализ результатов:**
   * **Кейс 1 (200 байт):** Записано 200 байт. Занято на диске: **`0 байт`**. Причина: файл целиком поместился в 1024-байтную запись MFT.
   * **Кейс 2 (2000 байт):** Записано 2000 байт. Занято на диске: **`4096 байт`**. Причина: 2000 байт превышают объем свободной памяти в записи MFT, поэтому файл стал нерезидентным и занял ровно 1 кластер диска (4 КБ).

### Задача 4. Эффект блокировки потока при синхронном вводе-выводе

* **Исходный файл для копирования:** [`task4_sync_blocking_demo.cpp`](task4_sync_blocking_demo.cpp)

#### Условие
Написать простую консольную программу, которая пытается делать два дела одновременно: имитировать работу интерфейса (выводить тики в цикле) и по команде пользователя вызвать тяжелое синхронное чтение файла с диска, демонстрируя эффект замирания потока.

#### Построчный разбор механизма блокировки:
1. `Sleep(500);` — имитирует обработку событий пользовательского интерфейса (GUI) в цикле. Поток находится в состоянии `Running`.
2. `ReadFile(hFile, buffer, bufferSize, &bytesRead, NULL);` — **синхронный вызов**.
3. **Что происходит внутри ядра ОС Windows:**
   * Поток переходит в режим ядра через системный вызов `syscall`.
   * Ядро формирует пакет `IRP` и передает его дисковому драйверу накопителя.
   * Поскольку флаг `FILE_FLAG_OVERLAPPED` отсутствует, планировщик Windows усыпляет вызывающий поток, переводя его из состояния `Running` в состояние **`Waiting (Blocked)`**.
   * Поток полностью перестает получать кванты процессорного времени. В консоли замирает бегущий счетчик тиков, а любое GUI-окно такого процесса переходит в статус **«Не отвечает» (Not Responding)**.
4. **Пробуждение потока:**
   * Когда контроллер накопителя завершает передачу данных в память, генерируется аппаратное прерывание.
   * Драйвер диска завершает пакет IRP.
   * Планировщик Windows переводит поток в состояние `Ready`, а затем запускает его на свободном ядре процессора.
   * Функция `ReadFile` возвращает управление, и поток продолжает работу.
