## Ключевые выводы и системные механизмы

1. **Асинхронный ввод-вывод (`FILE_FLAG_OVERLAPPED`):**
   * Позволяет выполнять дисковые операции через контроллер прямого доступа к памяти (DMA) без блокировки вызывающего потока.
   * Требует ручного указания 64-битного файлового смещения в структуре `OVERLAPPED` и обнуления неиспользуемых полей.
2. **Файловая система NTFS и таблица MFT:**
   * Запись MFT имеет фиксированный размер 1024 байта (1 КБ).
   * Файлы объемом до ~700 байт (Кейс 200 байт) сохраняются прямо внутри MFT (**резидентные атрибуты**), не занимая ни одного физического сектора на дисковом разделе.
   * Файлы большего размера (Кейс 2000 байт) становятся **нерезидентными**, получая физические кластеры на диске.
3. **Гранулярность выделения памяти (`Allocation Granularity`):**
   * Смещение для системного вызова `MapViewOfFile` обязано быть строго кратно 64 КБ (65 536 байт), иначе ядро завершит операцию с ошибкой `ERROR_MAPPED_ALIGNMENT (код 1132)`.
4. **Небуферизированный прямой I/O (`FILE_FLAG_NO_INTERMEDIATE_BUFFERING`):**
   * Обходит кэш операционной системы. Требует строгого аппаратного выравнивания адреса буфера в ОЗУ, смещения и размера кратно размеру сектора диска (4096 байт). Несоблюдение вызывает ошибку `ERROR_INVALID_PARAMETER (код 87)`.
5. **Накладные расходы TLB Flush при частом переключении окон маппинга:**
   * При каждом вызове `UnmapViewOfFile` ядро Windows вынуждено перестраивать таблицу страниц процесса и инициировать аппаратную инструкцию процессора `INVLPG`, инвалидируя кэш ассоциативной трансляции адресов (**TLB Flush**), что приводит к существенным задержкам при частых случайных операциях.
