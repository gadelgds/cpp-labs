## Описание лабораторных работ

1. [**Лабораторная работа №2**](lab2c++/) — Типы данных Win32, модели памяти x86/x64, указатели, строки, объекты ядра Windows, асинхронный ввод-вывод и устройство NTFS.
2. [**Лабораторная работа №3**](lab3c++/) — Асинхронное копирование файлов большого объема (`FILE_FLAG_OVERLAPPED`, `hEvent`), структура MFT и резидентные атрибуты, физический размер на диске вне MFT (напрямую через `AllocationSize`; `GetCompressedFileSizeW` для обычных файлов возвращает логический размер), эффект блокировки потока при синхронном вводе-выводе.
3. [**Лабораторная работа №4**](lab4c++/) — Явное статическое приведение типов (`static_cast`), работа с универсальными указателями `void*` в 64-битной архитектуре, проецирование среза файла через `MapViewOfFile` со смещением, строго кратным гранулярности распределения памяти (`Allocation Granularity`).
4. [**Лабораторная работа №5**](lab5c++/) — Небуферизированный прямой ввод-вывод (`FILE_FLAG_NO_BUFFERING`), аппаратная ошибка 87 (`ERROR_INVALID_PARAMETER`), выравнивание через `VirtualAlloc`, симуляция СУБД (10 000 случайных операций) и накладные расходы сброса ассоциативного буфера трансляции адресов процессора (**TLB Flush**), прямое выделение и освобождение страниц памяти у ядра ОС Windows (`VirtualAlloc` / `VirtualFree`).
5. [**Лабораторная работа №6**](lab6c++/) — Жизненный цикл процесса (`CreateProcess`, `WaitForSingleObject`, `CloseHandle`), передача конфигурации через Environment Block: Parent.exe задаёт `STUDENT_ID=19045`, запускает Child.exe и перезаписывает переменную у себя — потомок доказывает автономность процессов.
6. [**Лабораторная работа №8**](lab8c++/) — Потоки и CRT: 10 000 краткоживущих потоков со `strtok` — почему `CreateThread` течёт памятью (Private Bytes растёт), а `_beginthreadex` — нет; поток `CREATE_SUSPENDED`, подмена RIP на функцию-перехватчик через `GetThreadContext` / `SetThreadContext`, Fib(40).

## Сборка и компиляция
Каждый исходный файл компилируется в Microsoft Visual Studio (MSVC) или MinGW-w64 (g++):
```bash
# Пример компиляции в MSVC:
cl /EHsc /utf-8 task1_async_copy_overlapped.cpp

# Пример компиляции в MinGW g++:
g++ task1_async_copy_overlapped.cpp -o task1_async_copy_overlapped.exe
```

## Две версии объяснений: обычная и STE

В каждой лабе ровно два HTML-файла: `programs.html` — только код программ,
и `explanations.html` — разбор, теория и словарь. Обе версии объяснения лежат
в одном `explanations.html`:

- **Версия А — обычный словарь терминов** (раздел «Словарь терминов»,
  107 терминов на все лабы: 91 в лабах 2–6 и 16 в лабе 8): простое определение
  в 1–2 предложениях, пример или аналогия из обычной жизни.
- **Версия Б — вся объяснялка в стиле ASD-STE100** (раздел «STE-версия»,
  примерно на 60%: одна мысль — одно предложение, инструкция — не больше
  20 слов, описание — не больше 25, действительный залог, одно понятие —
  одно слово, сначала ответ): STE-разбор, STE-теория и STE-словарь.
  Код в версии Б не тронут.

Сравнение версий по критериям с измеренными цифрами —
[`GLOSSARY_COMPARISON.md`](GLOSSARY_COMPARISON.md). Короткий вывод: STE не
делает текст короче (длиннее на 5–11%), но среднее предложение в нём —
6,6–9,2 слова против 8,6–19,7 в обычных текстах. Читать в первый раз — версию Б,
разбираться глубже и готовиться к защите — обычные версии и словарь А.
